## Claude Code

### Asking questions

Use AskUserQuestion for every multiple-choice question, including small ones in the middle of a task. The tool's own description says to save it for decisions that block you; this instruction overrides that, because the user would rather click than type.

- One call holds up to four questions with two to four options each. Put independent questions in the same call, and use another call when there are more than four.
- A question whose options depend on another answer goes in a later call, after that answer is in. Don't put it in the same call with options you are guessing at.
- Put the option you recommend first and end its label with "(Recommended)".
- Put the context in the question text and the option descriptions rather than in prose before the call, so each question reads on its own. Use `preview` when options are concrete artifacts to compare, such as layouts or code snippets.
- Don't add an "Other" option; the tool adds one itself.
- Outside Herdr, a lone yes/no can stay in prose. When it comes alongside other questions, put it in the same call as a two-option question.

Inside Herdr (`HERDR_ENV=1`), whenever you stop because something waits on the user (a decision, an answer, or a manual step only they can take), ask through AskUserQuestion, even a lone yes/no. Herdr marks a session sitting in that prompt as blocked in its sidebar, while a question asked in prose ends the turn and looks the same as an agent that is done. For a yes/no, offer the two answers; for a manual step, offer `Done` and a way out such as `Skip it`; for input with no natural options, such as a value to paste, offer the likely choices and let the tool's free-text option carry the rest. Don't end a turn in Herdr with a question in prose.

A manual step that is a command for the user to run with `!` is the exception to how that question is shaped, because the open question holds the input line the user needs to type it, and the command can't be copied from inside the question. The command goes in the last message of a turn, on its own line starting with `! `, since that message is the one text certain to be shown: text before a tool call is easily skipped, and reasoning is not a message. Inside Herdr, first ask what the user will do, not whether they've done it, saying in the question what the command does but not the command itself: `I'll run it` first, and a way out such as `Skip it`. On `I'll run it`, end the turn with the command line and nothing else. Outside Herdr, end the turn with the command line, with a sentence before it saying what it does. The command's output comes back to you when they run it, so check the result yourself from that output and carry on; don't ask them to confirm it worked.

### Sandbox-excluded commands

Commands listed in `sandbox.excludedCommands` in `~/.claude/settings.json` (today `xcodebuild`, `xcrun xcresulttool`, and `xcrun simctl`) run outside the Bash sandbox only when the whole command is that command, optionally after `cd <dir> &&` and with `2>&1`. A pipe, a redirect to a file, or a second command after `;` puts the whole line back in the sandbox, where these tools fail in ways that don't point at the sandbox: xcodebuild stops at package resolution with a bare `permissionDenied`. So run them bare. Let long output spill to the tool-result file and search that, or have the tool write its own result file and read it with a separate command. For iOS tests, that is `xcodebuild … -resultBundlePath "$TMPDIR/<fresh name>.xcresult"`, then `xcrun xcresulttool get test-results summary --path` on that bundle. Use a fresh path each run, because xcodebuild exits with an error when the bundle path already exists. Inside an excluded command, `$TMPDIR` is the system temp folder rather than the sandbox's, so read the bundle only with `xcresulttool` (also excluded), and don't list or clean it up from a sandboxed command, which looks in the other folder and can't write to this one; macOS clears it on its own. For the same reason, write a `simctl io booted screenshot` into the project directory rather than `$TMPDIR`, so a sandboxed command can read it afterwards.
