# Herdr app settings

This file covers which of the Herdr desktop app's files these dotfiles manage and why; load it before changing anything in this directory.

The Herdr desktop app (`herdr-app`) keeps its whole interface as files in `~/.config/herdr-app/`, and its Settings screen writes `settings.json` itself (zoom, appearance, contrast, telemetry). So that file's source is a chezmoi modify-template, `modify_settings.json`, which reads the live file and sets only the keys we manage, as the `modify_` scripts for Claude's and Codex's settings do; it needs no interpreter because chezmoi's own `fromJson` and `setValueAtPath` are enough. The app ships no Tokyo Night, so `themes/tokyo-night.json` is ours; the app leaves theme files it didn't write alone. Keys stay on the app's defaults, and the shipped layouts and mods are left unmanaged, because Herdr replaces them on every start and personal changes to them go through clones.

`layouts/personal.json` is that kind of clone: the shipped `main` layout copied as-is, except that its bottom bar (the `status` block) becomes a `status-row` row holding that block and an `ai-usage` block at its right end. It is a snapshot, so changes Herdr later makes to `main` don't reach it; to pick them up, re-copy `main.json` and wrap `status` again. The block shows `mods/ai-usage/`, which runs `~/.local/bin/ai-usage --json windows` every minute. That is cheap because the script's shared cache decides when the providers are actually asked (see `dot_local/bin/AGENTS.md`). Each service is one unlabeled glyph of nested rings, one per limit window with the longest inside, painted with gpui-kit's `PathBuilder` so any percent draws in theme colors; hovering names the service and gives the numbers. Color goes by pace rather than the raw percent, because a high weekly figure late in the week is normal while a modest 5-hour figure early in the window is the real warning. The mod takes pace from the script's `ahead_of_pace` rather than computing it (its definition and reasons are in `dot_local/bin/AGENTS.md`): how far a window is ahead of the even rate that reaches 100% exactly at the reset, the measure the retired `choose-agent` skill used for backpressure but without its 90% headroom, so the color is exact: any amount ahead means on track to run out, and turns the ring yellow; 10% of the window ahead, or the limit itself, turns it red. The tooltip shows how long until the window is back on pace with no further use. A layout block can't size itself to its content, so the mod measures its content and resizes its own block's width to fit; clicking it switches to the tab named "AI usage" if one exists, else opens one running the live `ai-usage` view. `programs.json` gives that terminal its own name and icon (`mods/ai-usage/icon.svg`); without the entry Herdr, which looks through uv to the script it runs, finds no `ai-usage` program and shows uv's icon.

The bottom bar also holds `reviews-badge`, which shows `mods/reviews/`, a GitHub review queue. The same mod runs in two places, told apart by its props. The badge copy runs `~/.local/bin/github-review-queue --all` every five minutes for each GitHub repo a local space is in (see `dot_local/bin/AGENTS.md` for what counts as reviewed; `--all` because the mod also needs the reviewed PRs, to keep one listed while its session works or waits on me and to keep its mute), puts the result in shared state, and reads "Reviews: <n>", the number of PRs the Reviews tab lists, with a red dot in front while a review session needs the owner. At zero it stays visible as a dim "Reviews", so the Reviews tab is always one click away. The mod reads no files from the `github-pr` skill; starting `/github-pr review <n>` is its only tie to it.

The copy in a Reviews tab lists the PRs of every repo in one list, each with its repo under its number, in an order picked from its Sort menu (oldest first by default, from the queue's `created_at`; the choice is shared state, `reviews.sort`), with a terminal pane split beside it as a viewer. Each review's Claude session, `/github-pr review <n>`, runs in the repo's main checkout as a herdr-core terminal with no tab of its own (`hc run --bg --no-parent`), which keeps the tab bar from growing a tab per PR. Its `herdr-reviews.*` labels (repo, number, title) are how the mod finds it again, and because the queue keeps no state of its own, finding it is what stops a second session reviewing the same PR. Clicking a row shows its session in the viewer with `terminal.show`. A tab-less session gets none of Herdr's attention cues, so the badge copy notifies when one turns blocked or finished. There is no close button: the badge copy kills and removes a session once its PR has left the list (reviewed at its head, merged, closed, or no longer asked) and the agent isn't working or waiting on the owner. It acts only on a queue it read itself since starting, and only for repos whose read succeeded, so a failed read or a stale queue from before a restart never closes a session; an abandoned one can be ended with `/exit` in the viewer. Right-clicking a row opens the same mod as a popup menu (`props.menu`) with Mute and Open on GitHub. A muted PR drops, in greys only, to a Muted group at the bottom and stays out of the badge's count and Review all, with no Review button of its own; mutes live in shared state (`reviews.muted`) and last until unmuted or until the PR leaves the queue of a repo that was read, so a failed read never forgets them. A PR that someone besides me and its author has already reviewed (the queue's `other_reviewers`, which leaves out bots) is muted automatically the first time the poller sees it that way, `reviews.automuted` maps each PR muted that way to whether the mute is still the automatic one, so it happens only once (an unmute sticks, even after more reviews arrive) and the row can say why it's muted: "already reviewed by …" for an automatic mute, "muted by you" once I've muted or unmuted it by hand. That record is pruned the same way as the mutes. Sessions aren't started with `--rm`, so one that dies at launch stays in `hc ls --all` to be inspected until its PR leaves the list. `DEMO` at the top of `main.js` swaps the queue for made-up PRs, for trying the interface; sessions are real either way.

The app replaced the terminal Herdr (`herdr`) for daily use. The terminal version's `~/.config/herdr/config.toml` (source `dot_config/herdr/config.toml.tmpl`) is a separate program's config, kept for occasional use, and the nvim blocks keyed on `HERDR_ENV` and `HERDR_PANE_ID` run only there: the app sets `HC_TERMINAL_ID` instead, and names panes from `programs.json` and the program it sees running.
