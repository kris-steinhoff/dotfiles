# Herdr app settings

This file covers which of the Herdr desktop app's files these dotfiles manage and why; load it before changing anything in this directory.

The Herdr desktop app (`herdr-app`) keeps its whole interface as files in `~/.config/herdr-app/`, and its Settings screen writes `settings.json` itself (zoom, appearance, contrast, telemetry). So that file's source is a chezmoi modify-template, `modify_settings.json`, which reads the live file and sets only the keys we manage, as the `modify_` scripts for Claude's and Codex's settings do; it needs no interpreter because chezmoi's own `fromJson` and `setValueAtPath` are enough. The app ships no Tokyo Night, so `themes/tokyo-night.json` is ours; the app leaves theme files it didn't write alone. `keys.json` is managed the same way as `settings.json`, by `modify_keys.json`, which adds cmd-shift-o to open the plan mod's picker. Herdr upgrades its default shortcuts only in a keys file nobody has touched, so adding a key means new defaults from later releases have to be added by hand, as the template does for 0.1.16's cmd-m (minimize) and cmd-a (select all in a terminal); check each release's notes for more; the template writes nothing when there is no file yet, since a file holding only our key would replace every default. The shipped layouts and mods are left unmanaged, because Herdr replaces them on every start and personal changes to them go through clones.

`layouts/personal.json` is that kind of clone: the shipped `main` layout copied with two differences: its bottom bar (the `status` block) becomes a `status-row` row holding that block and an `ai-usage` block at its right end; and the sidebar's `sidebar-lists` column gains a `reviews` block after `agents`. It is a snapshot, so changes Herdr later makes to `main` don't reach it; to pick them up, re-copy `main.json` and make the change again. The block shows `mods/ai-usage/`, which runs `~/.local/bin/ai-usage --json windows` every minute, whenever the script's cache folder (`~/.local/state/ai-usage/`) changes, and when clicked. That is cheap because the script's shared cache decides when the providers are actually asked (see `dot_local/bin/AGENTS.md`). Watching the cache keeps the block in step with the live view, which re-reads the cache every second: without it, a fetch the live view made, or its Ctrl-R, reached the block up to a minute later. Each service is one unlabeled glyph of nested rings, one per limit window with the longest inside, painted with gpui-kit's `PathBuilder` so any percent draws in theme colors; hovering names the service and gives the numbers. Color goes by pace rather than the raw percent, because a high weekly figure late in the week is normal while a modest 5-hour figure early in the window is the real warning. The mod takes pace from the script's `ahead_of_pace` and the color from its `level` rather than computing them, so the rings and the live view's bars always agree (definitions and reasons are in `dot_local/bin/AGENTS.md`). Pace is how far a window is ahead of the even rate that reaches 100% exactly at the reset, the measure the retired `choose-agent` skill used for backpressure but without its 90% headroom, so the color is exact: any amount ahead means on track to run out, and turns the ring yellow; 10% of the window ahead, or the limit itself, turns it red. The theme has no orange, so the `high` level, which the live view shows in orange, shows in yellow. The tooltip shows how long until the window is back on pace with no further use. A layout block can't size itself to its content, so the mod measures its content and resizes its own block's width to fit; clicking it shows a snapshot, `ai-usage --once`, in a dialog over the window rather than opening a tab, since a glance is all a click is usually for. The snapshot runs as a herdr-core terminal with no tab (`hc run --bg --no-parent --rm`, labelled `herdr-ai-usage`), and the dialog is an `openOverlay` layout holding a terminal block for it rather than `terminal.peek`, because the peek's bar offers to keep the terminal as a tab and can't be replaced from a layout. The terminal waits 0.3 s before printing, so the dialog has already sized it: a snapshot doesn't redraw at a new width. It then waits for a key and ends, and Herdr closes an overlay whose terminal ends; a click beside the dialog closes it but leaves the terminal waiting, so each click first kills the labelled one before. `programs.json` gives a tab running the live view (`ai-usage` with no flags) its own name and icon (`mods/ai-usage/icon.svg`); without the entry Herdr, which looks through uv to the script it runs, finds no `ai-usage` program and shows uv's icon.

The sidebar's `reviews` block shows `mods/reviews/`, a GitHub review queue. The same mod also runs as its own popup menus and in a leftover Reviews tab, told apart by its props. The sidebar copy (`props: { sidebar: true }`) runs `~/.local/bin/github-review-queue --all` every five minutes for each GitHub repo a local space is in (see `dot_local/bin/AGENTS.md` for what counts as reviewed; `--all` because the mod also needs the reviewed PRs, to keep one listed while its session works or waits on me and to keep its mute), puts the result in shared state, and lists it in the sidebar's width, around 250px. Only the personal layout has the block, so in any other layout nothing checks or shows the queue. Herdr starts a mod's copy only the first time its block shows, then keeps it running while the sidebar is folded or hidden; so if Herdr launches with the sidebar hidden, nothing checks the queue, notifies, sets the Dock badge, or closes sessions until the sidebar is shown. The mod reads no files from the `github-pr` skill; starting `/github-pr review <n>` is its only tie to it.

The block's header follows the agents header: "Reviews" and the count of listed PRs that aren't muted, a ↻ that asks for a check (its tooltip says when the last check was and when the next is), and a ⋯ menu, the same mod as a popup (`props.menu.list`), holding the sorts (oldest first by default, from the queue's `created_at`; the choice is shared state, `reviews.sort`), Fit to list while the block has a dragged height, and, when more than one PR can be started, Review all. The popup can't start sessions itself, so Review all writes a time to `reviews.startAll` and the sidebar copy acts on it, only on a time after it started, since shared state outlives restarts and a leftover request would otherwise start every PR again. The PRs of every repo are one list. Each PR is two lines: its number (a click opens it on GitHub), its title, and at the right a ▶ that starts a review and peeks at it, or the session's status as a dot in its stage color, or the agents list's compact ! pill while it needs me; then the repo without its owner (with it when two watched repos share a name), the first word of the author's name, the age, and the size. Hovering a row lists the rest, one per line: full title, full repo, files changed, what it's stacked on, who else reviewed it, whether it asks me by name, and its Jira keys. A repo whose read failed is one dim line with the error as its tooltip. Before the first check a line says so; once the queue is read and nothing waits, the block is just its header.

Each review's Claude session, `/github-pr review <n>`, runs in the repo's main checkout as a herdr-core terminal with no tab of its own (`hc run --bg --no-parent`), which keeps the tab bar from growing a tab per PR. Its `herdr-reviews.*` labels (repo, number, title) are how the mod finds it again, and because the queue keeps no state of its own, finding it is what stops a second session reviewing the same PR. Clicking a row peeks at its session over the current tab with `terminal.peek`, the way Herdr's agents list shows a tab-less terminal, and ▶ peeks at the new session once Herdr lists it; Review all peeks at none. A tab-less session gets none of Herdr's attention cues, so the sidebar copy notifies when one turns blocked or finished, except while I'm looking at it (`focused()` names the terminal that has input, a peeked one included). The notification's action is `terminal.peek` with the session's address, so clicking it peeks at the session. The sidebar copy also puts the number of blocked sessions on Herdr's Dock icon with `setBadge`. There is no close button: the sidebar copy kills and removes a session once its PR has left the list (reviewed at its head, merged, closed, or no longer asked) and the agent isn't working or waiting on the owner. It acts only on a queue it read itself since starting, and only for repos whose read succeeded, so a failed read or a stale queue from before a restart never closes a session; an abandoned one can be ended with `/exit` in its peek. Sessions aren't started with `--rm`, so one that dies at launch stays in `hc ls --all` to be inspected until its PR leaves the list.

Right-clicking a row opens the same mod as a popup menu (`props.menu`) with Mute and Open on GitHub. Muted PRs fold, in greys only, under a "▸ Muted (n)" line at the bottom, closed at start, and stay out of the count and Review all, with no ▶ of their own; a muted row's second line starts with why it's muted and drops the size. Mutes live in shared state (`reviews.muted`) and last until unmuted or until the PR leaves the queue of a repo that was read, so a failed read never forgets them. A PR that someone besides me and its author has already reviewed (the queue's `other_reviewers`, which leaves out bots) is muted automatically the first time the poller sees it that way. The exception is a PR that asks me for review by name rather than through a team (the queue's `requested_directly`): it is never muted automatically, an automatic mute made before the request arrived is lifted, and its tooltip says "asked of you by name" beside who else reviewed it. `reviews.automuted` maps each PR muted that way to whether the mute is still the automatic one, so it happens only once (an unmute sticks, even after more reviews arrive) and the row can say why it's muted: "already reviewed by …" for an automatic mute, "muted by you" once I've muted or unmuted it by hand. That record is pruned the same way as the mutes. `DEMO` at the top of `main.js` swaps the queue for made-up PRs, for trying the interface; sessions are real either way.

A layout block can't size itself to its content, so the sidebar copy measures its content and resizes its own block's height, from just the header (41px) up to 360px, past which the list scrolls. It measures the content column inside the scrolling area, not the area itself, which takes the block's height and would chase its own resize. Dragging the block's divider gives it a height by hand. The copy keeps the resizes it has asked for until the block shows them, and reads a change of height in `layout()` while any are pending as them landing, in order; only a change with none pending is a drag. So its own resizes never count as one, even when Herdr shows them late, or holds one short of what was asked because the spaces and agents blocks need their room; a held height is kept rather than asked for again, and a resize that changes nothing within 2 seconds counts as held where the block was. It then stops fitting the list, which scrolls inside the dragged height, and keeps that height in shared state (`reviews.height`), because Herdr keeps the dragged size across restarts but a copy that forgot the drag would fit over it. A drag below the header is raised to 41px so the ⋯ menu stays in reach, and its Fit to list clears the height and returns the block to fitting its list. `personal.json` sets no `max` on the block, so a drag can go past 360px; the agents and spaces blocks' mins bound it. Herdr folds the sidebar to a narrow rail below 160px, and the copy tells the rail by that width, as the agents mod does. In the rail the block is 28px and shows just the count, or a dim R at zero, with a red dot in front while a session needs me; `personal.json` sets the block's `min` to 28 because Herdr enforces it. Clicking it unfolds the sidebar the way the agents mod's toggle does: `layout.resize` of `sidebar` to `sidebar.width` in shared state (268 if unset), and `sidebar.collapsed` set false. The rail's height is always the copy's, so nothing there counts as a drag; leaving the rail, the block returns to its dragged height if it has one, or else to the height it last measured. A Reviews tab still open from before the list moved to the sidebar is a pane mod with no props, so it would keep running this mod: a copy with no props only says, centered, that reviews now show in the sidebar of the personal layout and to close the tab, and neither polls nor acts.

`mods/plan/` shows a local plan in a Plan tab the way the claude.ai plan page does: progress, Needs attention, approach, done-check, the PR stack, collapsible task cards, and the journal. cmd-shift-o (`mod.open:plan`) opens the same mod as a picker of the plans in the focused space's repo, found through the git common dir so a linked worktree finds the main checkout's `.plans/`, and a folder or slug can be typed instead. The picker opens the plan in a tab of its own (`props: { plan: <folder> }`), because the page's layout needs a tab's width, or selects the tab already showing it. That tab is named for the plan's folder and found again by that name, since `panes()` doesn't expose a mod pane's props. Edit `find.js` for finding plans and their tabs, `main.js` for the picker, and `plan.js` and `plan-view.js` for the Plan tab.

The mod doesn't start or track drivers. `/drive-implementation` runs in any tab, it starts its agents as `hc` sub-agents (`dot_agents/skills/drive-implementation/`), and Herdr already marks a driver waiting on a question as blocked, so a panel that started each driver in a space and checkout of its own and showed every agent's status from `hc` labels was more machinery than the work needed.

The Plan tab reads the plan's files itself rather than through `plan-store`, since the files are the store's documented layout and a refresh then starts no process, and rereads them when `watchFolder` reports a change, with a 30-second timer behind it, because on Linux `watchFolder` skips git-ignored folders and `.plans/` is ignored. It is read-only: a local plan's driver asks its questions in its own session with the structured question tool, which Herdr shows as blocked, so an open question offers a button to the driver instead of a form; a view that wrote would go through `plan-store --as herdr`. The driver is the live terminal running an agent whose `plan.driver` label is the plan's folder, which `/drive-implementation` has it set; a tab's shell outlives the agent run in it, so a terminal without its agent doesn't count. `plan.js` repeats the page's derived views (when a running plan counts as blocked, the PR chain, answered questions folded into the journal, and the dependency graph's layout), so a change to the guide's schema or to how the page shows a plan needs the same change there. The graph's edges are painted with gpui-kit's `PathBuilder` and `window.paint_path`, the calls the ai-usage rings use, and its tasks are positioned boxes. The layout follows the page: the title and progress stay pinned at the top, and below them, when the tab is wide enough, the graph has its own scrolling column on the left of the plan, standing in for the page's sticky side column; narrower, a button in the header shows it above the plan. Picking a task in the graph highlights its chain, and picking its id also scrolls to its card and highlights the card briefly. A gpui-kit scroll handle can bring only a direct child of its scroll area into view, so the plan's column is a flat list of blocks with each task card its own block, rather than sections nesting their contents. The highlight is an overlay whose opacity fades out, since opacity, size, and position are all gpui-kit animates. A plan page has no Plan tab, since the mod can't read an artifact's database. `demo.js` holds a made-up plan's documents, and with `DEMO` on in `main.js` the picker opens it in a real Plan tab.

`herdr-app check` runs a mod's `init()` for real, so the reviews mod stops polling (`polls()`) and ai-usage stops before its first fetch while `checking()` is true; otherwise a check would read the review queue, write shared state, close review sessions, or ask the AI providers. The plan mod only reads, so it needs no guard. A check also writes `gpui-kit.d.ts` and `jsconfig.json` into a mod folder it checks. Delete them rather than committing them, because chezmoi would deploy them to `~/.config/herdr-app/mods/`.

The app replaced the terminal Herdr (`herdr`) for daily use. The terminal version's `~/.config/herdr/config.toml` (source `dot_config/herdr/config.toml.tmpl`) is a separate program's config, kept for occasional use, and the nvim blocks keyed on `HERDR_ENV` and `HERDR_PANE_ID` run only there: the app sets `HC_TERMINAL_ID` instead, and names panes from `programs.json` and the program it sees running.
