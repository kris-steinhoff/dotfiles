# Herdr app settings

This file covers which of the Herdr desktop app's files these dotfiles manage and why; load it before changing anything in this directory.

The Herdr desktop app (`herdr-app`) keeps its whole interface as files in `~/.config/herdr-app/`, and its Settings screen writes `settings.json` itself (zoom, appearance, contrast, telemetry). So that file's source is a chezmoi modify-template, `modify_settings.json`, which reads the live file and sets only the keys we manage, as the `modify_` scripts for Claude's and Codex's settings do; it needs no interpreter because chezmoi's own `fromJson` and `setValueAtPath` are enough. The app ships no Tokyo Night, so `themes/tokyo-night.json` is ours; the app leaves theme files it didn't write alone. Keys stay on the app's defaults, and the shipped layouts and mods are left unmanaged, because Herdr replaces them on every start and personal changes to them go through clones.

`layouts/personal.json` is that kind of clone: the shipped `main` layout copied as-is, except that its bottom bar (the `status` block) becomes a `status-row` row holding that block and an `ai-usage` block at its right end. It is a snapshot, so changes Herdr later makes to `main` don't reach it; to pick them up, re-copy `main.json` and wrap `status` again. The block shows `mods/ai-usage/`, which runs `~/.local/bin/ai-usage --json windows` every minute. That is cheap because the script's shared cache decides when the providers are actually asked (see `dot_local/bin/AGENTS.md`). Each service is one unlabeled glyph of nested rings, one per limit window with the longest outside, painted with gpui-kit's `PathBuilder` so any percent draws in theme colors; hovering names the service and gives the numbers. Color goes by pace (where the window ends up at the current rate) rather than the raw percent, because a high weekly figure late in the week is normal while a modest 5-hour figure early in the window is the real warning. A layout block can't size itself to its content, so the mod measures its content and resizes its own block's width to fit; clicking it switches to the tab named "AI usage" if one exists, else opens one running the live `ai-usage` view. `programs.json` gives that terminal its own name and icon (`mods/ai-usage/icon.svg`); without the entry Herdr, which looks through uv to the script it runs, finds no `ai-usage` program and shows uv's icon.

The bottom bar also holds `reviews-badge`, which shows `mods/reviews/`, a GitHub review queue. The same mod runs in two places, told apart by its props. The badge copy runs the `github-pr` skill's `scripts/queue.py ready` every five minutes for each GitHub repo a local space is in, puts the result in shared state, and shows a count. The copy in a Reviews tab lists the PRs and starts each review in a tab running `claude "/github-pr review <n>"`, named `#<n> …`, in a space on that repo. That name is how it finds the tab again, and because the queue keeps no state of its own, finding the tab is what stops a second session reviewing the same PR. A review tab's Herdr agent status is what the queue shows as reviewing, needs you, or finished. The badge stays visible when nothing waits, reading "no reviews", so the Reviews tab is always one click away.

The older terminal Herdr's `~/.config/herdr/config.toml` is a separate program's config and stays as it is.
